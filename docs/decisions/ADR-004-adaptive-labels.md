# ADR-004: Adaptive ATR Label Threshold

## Status
Superseded by [ADR-007](ADR-007-detection-2-mae-filter.md) (Phase 17F, 2026-04-30) — the 3-class softmax framework this ADR operated within is no longer used; labels are now generated by the detection-2 + MAE filter scheme.

## Date
2026-03-10 (Phase 15 / v5 architecture)

---

## Context

The 3-class labeling scheme defines BIG_UP and BIG_DOWN as "price moves ≥ threshold within the forward window." The original fixed threshold was **50 NQ points** (originally chosen to represent roughly 1 ATR on a typical day).

With a fixed 50-point threshold on 66 days of training data (Oct–Dec 2025):
- BIG_DOWN: ~1% of bars
- CONSOLIDATION: ~98%
- BIG_UP: ~1%

This extreme class imbalance meant that inverse-frequency class weighting alone was insufficient. The model could achieve 98% accuracy by predicting CONSOLIDATION exclusively. Even with class weights, the first non-degenerate 3-class model (`model_v005_full`) achieved f1_macro=0.227 — barely above the degenerate floor.

The root problem: NQ volatility is not constant. A 50-point move is "big" in a quiet week (Oct 2025 realized vol ~0.8%) but routine in a volatile week (Dec 2025 vol ~1.5%). A fixed threshold labels the same market dynamics inconsistently across regimes.

---

## Options Considered

| Option | Class distribution | Pros | Cons |
|--------|-------------------|------|------|
| Fixed 50-point threshold | ~1% / 98% / 1% | Simple | Severe imbalance; threshold is regime-dependent |
| Percentile-based threshold | ~X% / (100−2X)% / X% by construction | Balanced by definition | Percentile changes meaning across regimes; hard to interpret |
| **Adaptive ATR threshold** (chosen) | ~21% / 55% / 24% at mult=3.0 | Calibrated to realized volatility; biologically meaningful threshold | Adds `adaptive_atr_mult` hyperparameter |
| Fixed higher threshold (100pt) | ~5% / 90% / 5% | Simple | Still imbalanced; 100pt is too rare to be predictable |

---

## Decision

Use an **adaptive ATR-scaled threshold**:
```
threshold(t) = ATR_60(t) × √60 × adaptive_atr_mult
```

Where:
- `ATR_60(t)` is the rolling Average True Range over 60 bars (5 min)
- `√60` scales from 5s ATR to a 5-minute horizon (by the square-root-of-time rule)
- `adaptive_atr_mult = 3.0` calibrated empirically to produce ~22% combined BIG_UP + BIG_DOWN rate

The multiplier `3.0` was selected by sweeping mult ∈ {1.0, 1.5, 2.0, 2.5, 3.0, 3.5, 4.0} and observing:
- At mult=3.0: ~24% BIG_DOWN / 55% CONSOLIDATION / 21% BIG_UP on 66-day window
- Class weights + adaptive threshold → `model_v006_adaptive` f1_macro=0.303 (vs 0.227 fixed)

Interpretation: "BIG" means "moved more than 3 standard deviations of the 5-second bar distribution, scaled to a 5-minute horizon." This self-adjusts as market volatility changes.

---

## Consequences

- **+** Model trained on v006 (adaptive): f1_macro 0.303 vs f1_macro 0.227 (fixed, v005) — 33% improvement
- **+** Class distribution is stable across different volatility regimes — training data is more consistent
- **+** `adaptive_atr_mult` is a tunable hyperparameter (included in HPO search space)
- **−** The threshold is now a function of recent realized volatility — label at bar t is not independent of recent price history
- **−** A BIG_UP at low volatility represents a different absolute point move than a BIG_UP at high volatility — post-trade PnL interpretation requires considering regime
- **Constraint**: Labels are computed at training time from the Parquet feature file price series. The Parquet files do not store labels — regenerate labels whenever `adaptive_atr_mult` or `forward_windows_bars` changes.

Config keys: `labels.adaptive_threshold: true`, `labels.adaptive_atr_mult: 3.0`  
Implementation: `src/training/labels.py`, `src/training/config.py` `LabelConfig`
